# 实验二设计方案：Python 调试、函数、异常处理与类

## 一、设计定位

实验一已经覆盖变量、字符串、列表、字典、条件判断和循环。实验二不宜继续横向堆积大量语法，而应解决学生最明显的学习障碍：程序出错后不知道从哪里开始检查。

本次实验的主线是：

> 复现错误 → 阅读报错 → 缩小范围 → 最小修改 → 用测试验证

在此基础上增加函数和异常处理，使学生能够把较长程序拆成可独立检查的小模块，并能够处理格式不正确的输入数据。

## 二、学习目标

完成实验后，学生应能够：

1. 区分语法错误、运行时错误和逻辑错误。
2. 从 traceback 的最后一行识别异常类型，并定位到自己的代码行。
3. 使用 `print()`、`type()`、`len()`、断点和单步执行检查程序状态。
4. 编写带参数和返回值的简单函数，理解“打印”和“返回”的区别。
5. 使用 `try/except ValueError` 处理数值转换失败，不使用空的 `except:` 隐藏错误。
6. 使用 `assert` 为函数设计最小测试，并覆盖正常、边界和异常输入。
7. 定义简单的实数类和复数类，理解对象、属性、方法以及常用魔法方法。
8. 综合使用函数、列表、字典和控制流，完成一份二分类模型预测日志的清洗与统计。

## 三、内容边界

本次讲授：

- traceback 与常见异常；
- 调试流程和 VS Code 断点；
- 函数、参数、返回值和局部变量；
- `try/except`；
- `assert` 与边界测试；
- 类、对象、`self`、`__init__`、`__repr__`；
- 复数加法、乘法和模长对应的 `__add__`、`__mul__`、`__abs__`；
- 列表中嵌套字典的数据处理。

本次暂不讲：

- 多层继承和抽象类；
- 装饰器、生成器；
- 递归；
- 第三方数据分析库；
- 复杂文件路径和工程结构。

## 五、课堂组织建议

### 1. 助教不直接公布修改后的整段代码

先让学生依次回答：

1. 错误能否稳定复现？
2. traceback 最后一行是什么？
3. 报错指向哪一行？
4. 这一行有哪些变量，它们的值和类型是什么？
5. 最小修改是什么？
6. 如何证明修改没有破坏其他情况？

### 2. 现场代码演示优先于逐页念 PPT

建议投屏 VS Code 或 notebook，故意制造错误并现场检查变量。每次演示只改变一个地方，让学生看到“现象—证据—修改—验证”的闭环。

### 3. 改错题按错误类型分组

- A 组：`SyntaxError`、`IndentationError`；
- B 组：`TypeError`、`IndexError`、`KeyError`；
- C 组：条件顺序、循环边界、累计变量等逻辑错误；
- D 组：函数忘记 `return`、异常处理范围过宽。

### 4. 评价方式

- notebook 中八道基础改错题和三道类练习的 `assert` 全绿，用于形成性练习；
- 平台使用五组标准输入输出数据判分；
- 实验报告保留错误现象、原因、修改和验证证据，不只提交最终代码。

## 六、综合实验

题目：二分类模型预测日志清洗与评估。

学生读取若干条预测记录，每条包含样本编号、真实标签、预测标签和置信度。程序需要跳过格式或取值不合法的记录，统计正确数、错误数、混淆矩阵、准确率、平均置信度以及置信度最高的错误样本。

该题覆盖：

- `input()`、`split()` 和类型转换；
- `try/except ValueError`；
- 函数参数与返回值；
- 列表中嵌套字典；
- 多分支条件判断；
- 累计变量与最大值更新；
- 并列时保留先出现记录；
- 零有效数据时避免除零；
- 固定格式输出和平台自动判题。

## 七、面向对象小实验

先定义只保存一个 `value` 属性的 `RealNumber`，再定义保存 `real`、`imag` 两个属性的 `ComplexNumber`。学生需要实现：

- `__init__`：初始化对象；
- `__repr__`：给出可用于调试的对象表示；
- `__add__`：复数加法；
- `__mul__`：复数乘法；
- `__abs__`：计算复数模长；
- `conjugate()`：返回共轭复数。

重点改错是复数乘法公式：

```text
(a + bi)(c + di) = (ac - bd) + (ad + bc)i
```

常见错误包括把实部写成 `ac + bd`、虚部漏掉一项、直接修改原对象，以及 `print()` 代替 `return`。这些问题适合用小规模 `assert` 定位。

实数和复数之间不强制设计复杂的自动类型转换。基础任务通过 `real.to_complex()` 显式转换；选做题再让 `RealNumber` 继承 `ComplexNumber`，讨论“数学上的子集”和“程序中的继承”是否总要完全对应。
