## 二、先区分三类错误（3—8 分钟）

### 1. 语法错误：程序还没有开始正常执行

```python
if score >= 60
    print("pass")
```

Python 在解析代码时就发现结构不合法，因此通常无法建立我们关心的函数调用过程。此时先检查报错箭头附近的冒号、括号、引号和缩进。

### 2. 运行时错误：程序执行到某一步无法继续

```python
score = "85"
print(score + 5)  # TypeError
```

程序已经执行，异常发生时存在调用栈。Python 会利用它生成 traceback，告诉我们程序经过了哪些调用才到达失败位置。

### 3. 逻辑错误：程序走完了，但答案不对

```python
score = 92

if score >= 60:
    level = "pass"
elif score >= 85:
    level = "excellent"
```

逻辑错误通常没有 traceback，因为 Python 不知道我们的真实意图。此时要比较预期结果与实际结果，并检查分支、循环和中间变量。

课堂提问：`92` 为什么得到 `pass`？如果没有报错，哪一条证据能证明程序走了哪个分支？

## 三、函数调用时到底发生了什么（8—14 分钟）

看一个普通的函数调用：

```python
def add_bonus(score):
    bonus = 5
    result = score + bonus
    return result


final_score = add_bonus(80)
```

执行 `add_bonus(80)` 时，可以先用下面这个简化模型理解：

1. 暂停调用者当前的工作；
2. 为 `add_bonus` 创建一个**栈帧**；
3. 在栈帧中保存本次调用的参数、局部变量，以及执行完后回到哪里；
4. 执行函数体；
5. `return` 后销毁本次栈帧，把结果交回调用位置。

栈帧可以想成一次函数调用的“工作台”。同一个函数调用两次，会产生两个不同的工作台，二者的局部变量互不混用。

多个函数互相调用时，栈帧按照“后进入、先退出”的顺序叠放，这就是**调用栈**：

```text
栈顶：add_bonus(score=80, bonus=5, result=85)  ← 当前正在执行
栈底：<module>                                 ← 调用 add_bonus 后正在等待
```

正常 `return` 时，最上面的栈帧弹出；调用者从原来的位置继续执行。

`return` 和 `print()` 的区别也可以从调用关系理解：`return` 把值交回等待中的调用者，`print()` 只是把内容显示到屏幕。函数如果只有 `print()` 而没有显式 `return`，调用者得到的是 `None`。

```python
def wrong_add(a, b):
    print(a + b)


result = wrong_add(2, 3)  # 屏幕显示 5
print(result)              # 调用者实际得到 None
```

> 精确到 Python 实现，栈帧还保存字节码执行位置等状态。课堂调试只需抓住三个要素：**调用的是谁、参数和局部变量是什么、结束后回到哪里**。

## 四、异常为什么会产生多层 traceback（14—20 分钟）

教师现场运行：

```python
def parse_score(text):
    return int(text)


def load_score(record):
    raw_score = record["score"]
    return parse_score(raw_score)


def build_report(record):
    score = load_score(record)
    return f"{record['name']}: {score}"


student = {"name": "小科", "score": "NA"}
print(build_report(student))
```

执行到 `int("NA")` 前，调用栈是：

```text
栈顶  parse_score(text="NA")
      load_score(record={"name": "小科", "score": "NA"})
      build_report(record={"name": "小科", "score": "NA"})
栈底  <module>
```

`int("NA")` 抛出 `ValueError` 后，`parse_score` 没有处理它，异常就交给调用者 `load_score`；后者也没有处理，就继续向上传播。这个沿调用栈逐层寻找异常处理器的过程叫做**栈展开**。如果一直没有找到合适的 `except`，程序停止并打印 traceback。

输出的核心结构类似：

```text
Traceback (most recent call last):
  File "demo.py", line ..., in <module>
    print(build_report(student))
  File "demo.py", line ..., in build_report
    score = load_score(record)
  File "demo.py", line ..., in load_score
    return parse_score(raw_score)
  File "demo.py", line ..., in parse_score
    return int(text)
ValueError: invalid literal for int() with base 10: 'NA'
```

`most recent call last` 的意思是：最早的调用写在上面，最近、最深的调用写在下面。因此可以这样读：

- 从下往上读，适合**诊断**：先看异常类型和触发点，再沿调用关系追查数据来源；
- 从上往下读，适合**复盘执行过程**：程序从入口经过哪些函数到达失败位置。

## 五、从触发异常的位置追到 bug 的根因（20—29 分钟）

### 1. 四步阅读 traceback

面对上一段 traceback，依次问：

1. **发生了什么？** 最后一行是 `ValueError`，`int()` 无法转换 `"NA"`。
2. **在哪里触发？** 最深一层是 `parse_score` 中的 `int(text)`。
3. **这个值从哪里来？** 向上一层看，`text` 来自 `raw_score`；再向上看，它来自 `record["score"]`。
4. **谁应该保证它合法？** 输入可能本来就含缺失值，因此根因不是 `int()` 坏了，而是程序没有定义“非法分数如何处理”的规则。

这说明：

> traceback 给出的是控制流证据；变量值和赋值关系给出的是数据流证据。溯源 bug 往往需要把两者合起来。

### 2. 报错行不一定是根因位置

```python
def average(total, count):
    return total / count          # 异常在这里触发


def summarize(scores):
    valid_scores = []             # 本应把合法分数加入列表
    total = sum(valid_scores)
    return average(total, len(valid_scores))
```

调用 `summarize([80, 90])` 会在除法处触发 `ZeroDivisionError`，但仅把 `/` 改掉并不能修复统计逻辑。真正需要追问的是：`count` 为什么为零？继续向上查，才会发现 `valid_scores` 从未填充。

可以把调查过程写成一条因果链：

```text
除数为 0
← len(valid_scores) 为 0
← valid_scores 是空列表
← 输入有两项却从未被加入
← 数据收集逻辑缺失
```

### 3. 一套可重复的调试闭环

```text
稳定复现 → 读取异常与调用链 → 检查栈帧中的值
         → 沿数据来源追根因 → 做最小修改 → 用测试验证
```

有 traceback 时从异常点出发；没有 traceback 时，从第一个“实际值不等于预期值”的位置出发。两种情况的共同本质都是：找到程序第一次偏离预期的地方。

## 六、如何观察调用栈和变量（29—32 分钟）

短程序可在函数入口或出错前临时打印：

```python
print("DEBUG parse_score", text, type(text))
```

较长程序更适合使用 VS Code 断点：

1. 在可能出错的行设置断点；
2. 打开 Run and Debug，选择 Python File；
3. 在 Variables 中查看当前栈帧的参数和局部变量；
4. 在 Call Stack 中切换到调用者，查看值是怎样传下来的；
5. Step Into 进入函数，Step Over 执行当前行，Step Out 返回调用者。

这里三个按钮对应的正是调用栈变化：Step Into 通常会压入新栈帧，Step Out 会运行到当前栈帧退出。

调试输出在平台提交前必须删除，否则会造成输出格式不匹配。

## 七、异常处理与测试（32—34 分钟）

如果 `"NA"` 是允许出现的脏数据，应在最清楚转换规则的小范围内处理：

```python
def parse_score(text):
    try:
        return int(text)
    except ValueError:
        return None
```

只捕获预期的 `ValueError`。不要用很大的 `try` 包住整段程序，也不要写空的 `except:`；否则 `KeyError`、拼写错误等程序缺陷也可能被误当成脏数据隐藏起来。

修复不是“这一次不报错”就结束，还要验证不同路径：

```python
assert parse_score("85") == 85       # 正常输入
assert parse_score("0") == 0         # 边界输入
assert parse_score("NA") is None     # 异常输入
```

`assert` 失败也会产生 traceback。最后一层告诉我们哪个断言失败，上层调用则帮助找到测试是如何到达这里的。

## 八、类：以二元组为基类建立更广泛的定义（34—39 分钟）

### 1. 为什么从“二元组”出发

二维向量 `(x, y)`、复数 `(a, b)`、平面坐标 `(x, y)` 都由两个分量组成。它们可以共享“保存两个分量、显示对象、转成普通元组”等结构，但运算含义并不相同。

这里的“二元组”指有序的两个分量，示例将基类命名为 `Pair`；它不是 Python 内置且不可变的 `tuple` 类型。

```python
class Pair:
    """保存两个分量的通用基类。"""

    def __init__(self, first, second):
        self.first = float(first)
        self.second = float(second)

    def __repr__(self):
        name = type(self).__name__
        return f"{name}({self.first}, {self.second})"

    def as_tuple(self):
        return (self.first, self.second)
```

基类只定义所有二元对象都成立的行为。不要急着在 `Pair` 中定义加法，因为“两个分量如何相加”取决于对象代表什么。

### 2. 同一结构，派生出不同数学语义

```python
class Vector2D(Pair):
    def __add__(self, other):
        return Vector2D(
            self.first + other.first,
            self.second + other.second,
        )

    def __abs__(self):
        return (self.first ** 2 + self.second ** 2) ** 0.5


class ComplexNumber(Pair):
    @property
    def real(self):
        return self.first

    @property
    def imag(self):
        return self.second

    def __add__(self, other):
        return ComplexNumber(
            self.real + other.real,
            self.imag + other.imag,
        )

    def __mul__(self, other):
        return ComplexNumber(
            self.real * other.real - self.imag * other.imag,
            self.real * other.imag + self.imag * other.real,
        )

    def __abs__(self):
        return (self.real ** 2 + self.imag ** 2) ** 0.5

    def conjugate(self):
        return ComplexNumber(self.real, -self.imag)
```

快速验证：

```python
v = Vector2D(3, 4)
z = ComplexNumber(3, 4)

assert isinstance(v, Pair)
assert isinstance(z, Pair)
assert v.as_tuple() == (3.0, 4.0)
assert z.as_tuple() == (3.0, 4.0)
assert abs(v) == 5.0
assert abs(z) == 5.0
assert (z * ComplexNumber(0, 1)).as_tuple() == (-4.0, 3.0)
```

这里要区分三件事：

- `Pair` 提供共同的数据结构和通用行为；
- 子类继承基类，并补充自己的数学语义；
- `v + ...` 会调用 `v.__add__(...)`，方法调用同样会产生栈帧，方法内部出错时也会出现在 traceback 中。

这个设计比“实数类派生复数类”更一般：继承表达的是程序结构上的共同点，不必机械照搬数学中的集合包含关系。

## 九、一分钟总结（39—40 分钟）

请学生补全下面六句话：

1. 每次函数调用都会创建一个新的 ________。（栈帧）
2. 多个栈帧以后进先出的顺序组成 ________。（调用栈）
3. 异常会沿调用栈向上寻找 ________。（匹配的异常处理器）
4. traceback 的最后一层通常是异常的 ________，但不一定是 bug 的根因。（触发点）
5. 追根因要同时检查调用关系和变量的 ________。（数据来源）
6. 修复之后要用正常、边界和异常输入进行 ________。（验证）

最后带走一句话：

> 不要只问“哪一行报错”，还要问“程序经过哪些调用来到这里，这个错误的值又是从哪里来的”。
