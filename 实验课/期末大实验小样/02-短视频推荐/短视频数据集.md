# 短视频数据与第一个预测实验

KuaiRand-Pure 来自短视频平台的匿名交互日志。**一行表示一次视频曝光，以及用户随后做出的反馈**。你可以先研究“只知道视频多长，能否预测用户会长时间观看”，再逐步加入用户与视频的历史信息。[返回选题入口](../../期末大实验选题说明.md)

## 先认识数据

本地原始包 `data/KuaiRand-Pure.tar.gz` 约 47.4 MB，共 2,622,668 条交互。2022 年 4 月 8–21 日的日志用于建立历史，4 月 22 日–5 月 8 日同时提供常规曝光和随机曝光。包内另有用户、视频基本信息和统计特征表，可按 ID 关联。

| 字段                   | 含义与用途                                                           |
| ---------------------- | -------------------------------------------------------------------- |
| `user_id`、`video_id`  | 用户和视频的编号，可以建立嵌入或二部图；编号的数值大小没有连续量意义 |
| `date`、`time_ms`      | 发生日期和时间戳，可确定某条记录之前有哪些历史                       |
| `duration_ms`          | 视频总时长，单位毫秒，曝光时已知                                     |
| `play_time_ms`         | 实际观看时长，曝光后才知道                                           |
| `long_view`、`is_like` | 长观看、点赞等反馈，可选作预测目标                                   |
| `tab`、`is_rand`       | 曝光场景，以及是否来自随机干预                                       |

视频不超过 18 秒时，`long_view=1` 表示看完；超过 18 秒时，表示至少看了 18 秒。因此，预测长观看时，可以把总时长作为输入，把实际观看时长留作反馈。将曝光后的信息放进输入，会使任务失去原来的预测含义。[官方字段说明](https://kuairand.com/)

## 从哪里开始

在本目录运行以下命令，原始包可以直接读取。

```bash
python3 -m pip install -r starter_requirements.txt
python3 starter.py
```

[starter.py](starter.py) 只依赖 NumPy 和 pandas，完成了四步。

1. **看样本。** 读取三份交互表，只保留 `tab=1` 和正的视频时长，打印前几行。
2. **按时间划分。** 4 月 18 日之前训练，18–21 日验证，22 日以后的常规、随机曝光分别测试。每部分固定随机抽取至多 20,000 行，方便先跑通。
3. **构造输入。** 对时长取 `log(1+秒数)`，再用训练集的均值和标准差缩放。输入 `X` 的形状为 `(样本数, 2)`，两列分别是常数项和缩放后的时长，目标 `y` 是同样数量的 0/1 标签。
4. **拟合和评价。** 比较始终输出训练集正例率的基线与时长逻辑回归。后者用梯度下降更新两个参数，输出验证、常规测试和随机测试的结果。

可以先打开 `features()` 看特征如何产生，打开 `fit_logistic()` 对照交叉熵的梯度，最后检查 `evaluate()` 中的指标。Log loss 与 Brier 分数越小越好，它们衡量预测概率与实际反馈的差距。准确率使用 0.5 阈值；当大部分标签为 0 时，一直预测 0 也可能很高，应同时看正例比例与概率指标。

## 简单流程

可以把问题定为“历史行为能否改善长观看预测，改善能否延续到随机曝光”。先复现时长基线，再从更早的日志提取用户或视频的历史信息，接入逻辑回归、嵌入模型或 MLP。在后续同一时段的常规曝光与随机曝光上分别评估，分析排序、预测概率和错误样本的变化。

## 关键公式与代码对应

对曝光样本 $i$，记视频总时长为 $d_i$ 秒，标签 $y_i\in\{0,1\}$ 表示是否达到长观看条件。起步脚本令 $a_i=\log(1+d_i)$，用训练集的均值 $\mu$ 和标准差 $s$ 构造输入，预测概率为

$$
x_i=\left[1,\frac{a_i-\mu}{s}\right]^\top\in\mathbb{R}^{2},
\qquad p_i=\sigma(w^\top x_i)=\frac{1}{1+\exp(-w^\top x_i)}.
$$

第一列常数对应截距，$w\in\mathbb{R}^{2}$ 为两个待学习参数。`features()` 完成缩放，`sigmoid()` 将得分转换成概率。

训练使用二元交叉熵。对 $n$ 条训练曝光，其损失和起步脚本中的梯度更新为

$$
\mathcal L(w)=-\frac1n\sum_{i=1}^{n}\left[y_i\log p_i+(1-y_i)\log(1-p_i)\right],
\qquad w\leftarrow w-\eta\frac{X^\top(p-y)}{n}.
$$

$X\in\mathbb{R}^{n\times2}$ 按行堆叠输入，$p,y\in\mathbb{R}^{n}$，$\eta$ 为学习率。`fit_logistic()` 对应这个更新；预测会不会越训越好，需要同时查看验证集损失。

若在更早的历史窗口内，用户 $u$ 有 $n_u$ 次曝光、其中 $k_u$ 次长观看，可构造平滑历史特征

$$
r_u=\frac{k_u+\alpha r_0}{n_u+\alpha}.
$$

$r_0$ 为这段历史的全局长观看率，$\alpha>0$ 控制向全局均值收缩的程度。视频历史率可同样构造。把 $(\log(1+n_u),r_u)$ 等量追加到输入，就能比较历史是否贡献额外信息。起步脚本尚未构造这些历史特征，可先固定一个早于模型训练的窗口，验证整条特征流水线。

除交叉熵外，起步脚本还输出 Brier 分数

$$
\operatorname{Brier}=\frac1m\sum_{i=1}^{m}(p_i-y_i)^2.
$$

$m$ 为当前评价集合的样本数。该分数和 Log loss 都评价概率误差，越小越好。可把预测概率分箱，比较每箱平均预测与实际长观看率；若增加 ROC-AUC，则可同时检查正负样本的排序。不同曝光组的正例率可以不同，比较每组模型相对其基线的变化更容易解释。

## 对比实验与结果分析

| 改变的因素                       | 保持一致的设置                         | 建议观察的输出                         |
| -------------------------------- | -------------------------------------- | -------------------------------------- |
| 仅时长、加用户历史、再加视频历史 | 同一曝光场景、历史截止时间和测试记录   | Log loss、Brier、按历史数量分组的误差  |
| 线性模型、嵌入与 MLP             | 同样的可用信息和数据划分               | 概率误差、训练耗时及具体失败样本       |
| 常规曝光与随机曝光               | 固定已训练模型，使用两组共有的评价日期 | 正例率、平均预测概率、校准图和排序指标 |

可以追问，只看时长为什么也可能有效？某模型排序较好，预测概率却普遍偏高，两个结论能否同时成立？加入用户嵌入后，历史很少或训练中没出现过的用户应怎样处理？把图传播层数增加后，收益来自关系还是额外训练预算？

也可改成点赞预测，研究正例稀少时指标的变化。改变目标后，重新核对哪些输入在预测时已经可知。

这些方向联系逻辑回归、损失与优化、神经网络及图表示学习。Pure 只保留候选视频池中的交互，行为序列存在缺口。原始视频统计表也需要核对统计时间后再使用。

## 参考论文

- Gao 等，2022，_KuaiRand: An Unbiased Sequential Recommendation Dataset with Randomly Exposed Videos_。先读数据采集和随机曝光部分，理解常规日志、随机干预与三个版本的边界。[论文](https://arxiv.org/abs/2208.08696)
- He 等，2017，_Neural Collaborative Filtering_。重点看用户与物品嵌入如何进入交互函数，可据此把两列时长输入扩成用户、视频和上下文表示。[论文](https://arxiv.org/abs/1708.05031)
- He 等，2020，_LightGCN: Simplifying and Powering Graph Convolution Network for Recommendation_。重点看用户与物品二部图上的邻居聚合，以及删减模块的对照思路。迁移到反馈预测时，需自行明确建图窗口和边的含义。[论文](https://arxiv.org/abs/2002.02126)
