# 共享单车数据集入口

Oslo City Bike 记录用户何时从哪个站点借车、何时归还到哪里。可以先研究一个站点的借车量，再考虑多个站点之间的关系。比如，在每天 08:00，根据已经发生的记录，我们可以预测 08:00–09:00 会有多少次借车。[返回选题入口](../../期末大实验选题说明.md)

## 先认识数据

我们提供提供 2025 年 8 月整月的 **176,415 条骑行记录**，CSV 约 36.7 MB。每一行是一趟已完成的骑行。下面是第一条记录的部分内容。

| 字段                 | 样例                               | 含义                             |
| -------------------- | ---------------------------------- | -------------------------------- |
| `started_at`         | `2025-08-01 03:00:18.565000+00:00` | 借车时间，原文件使用 UTC         |
| `ended_at`           | `2025-08-01 03:06:07.016000+00:00` | 还车时间                         |
| `duration`           | `348`                              | 骑行时长，单位为秒               |
| `start_station_id`   | `417`                              | 起点站号，可作为类别或图节点编号 |
| `start_station_name` | `Uranienborgparken`                | 起点站名                         |
| `end_station_id`     | `526`                              | 终点站号                         |

原文件还有起终点坐标和文字说明。`data/oslo-2025-08.csv` 包含全部站点的记录；`data/station-information.json` 是 2026 年 11 月 13 日保存的站点位置与容量快照。可从地理距离或训练期的站间骑行次数构建图。

## 简单流程

在本目录运行。Python 3.9 及以上版本可使用下面的依赖。

```bash
python3 -m pip install -r starter_requirements.txt
python3 starter.py
```

[starter.py](starter.py) 会自动选择训练期借车量最多的站点，完成小时聚合、特征构造、时间划分和三种预测比较。数据路径由脚本位置确定，运行时无需修改路径。第一次阅读可以依次看 `load_hourly_checkouts`、`make_examples` 和 `main`。

1. **把行程变成时间序列。** 按借车时间所在小时计数，并补齐连续小时。没有记录的小时计为零，表示这一小时观测到零次借车。
2. **确定输入和目标。** 目标 `y[t]` 是从时刻 `t` 开始的一小时借车量。输入为上一小时、上两小时、前一天同小时的计数，加上时钟和周末特征。前一天的历史不足时，丢弃对应样本。
3. **按时间划分。** 8 月 2–19 日训练，20–24 日验证，25–31 日测试。这个入门例子的统计范围设为当地 05:00–次日 01:00。
4. **建立对照。** 分别用“上一小时一样多”“昨天同小时一样多”和岭回归预测。岭回归的标准化参数来自训练集，正则强度用验证集选择。

你会看到训练、验证、测试的 `X` 形状分别为 `(360, 6)`、`(100, 6)`、`(140, 6)`，`y` 是对应长度的一维数组。每个 `X` 的行表示一个预测时刻，六列是六个输入特征。脚本输出 MAE，即平均每小时预测错多少次借车，数值越小越好。

可以在同目录的 notebook 中导入数据准备函数，查看每列的对应关系。构造历史特征的核心是 `shift(1)` 和 `shift(24)`，把已经观测到的计数对齐到未来目标。

```python
from starter import load_hourly_checkouts, make_examples

_, _, _, hourly = load_hourly_checkouts()
examples = make_examples(hourly)
print(examples[["checkouts", "lag_1", "lag_24"]].head())
```

## 一个可以完成的任务主线

可以把选题收束为“邻站信息能否改善下一小时借车量预测”。先完成起步脚本中的单站基线，画出一个工作日和一个周末的真实值与预测值。随后选择若干站点，保持时间划分和预测目标一致，比较只用本站历史、加入邻站均值、使用图神经网络三种表示。把高峰和低峰分开统计，检验总体改善是否也发生在最关心的时段。

## 关键公式与代码对应

记 $c_t$ 为单个站点在 $[t,t+1\mathrm{h})$ 内观测到的借车次数，$u_t$ 为当地小时数，$\omega_t$ 为周末指示量。起步代码的六维输入为

$$
x_t=\left[c_{t-1},c_{t-2},c_{t-24},\sin\frac{2\pi u_t}{24},\cos\frac{2\pi u_t}{24},\omega_t\right]^\top\in\mathbb{R}^{6}.
$$

$t-1$ 等下标表示相隔多少小时。`make_examples()` 中的 `shift` 确保前三项在预测时已经发生。连续历史窗口也可以组织成 $[B,h,F]$，分别表示批大小、历史小时数和每小时特征数，接入时间卷积或 Transformer。

设 $z_t$ 是用训练集均值和标准差缩放后的 $x_t$，岭回归的训练目标与预测为

$$
\min_{w,b}\ \frac{1}{n}\sum_{t\in\mathcal{T}_{\mathrm{train}}}(w^\top z_t+b-c_t)^2+\lambda\|w\|_2^2,
\qquad \widehat c_t=\max(0,w^\top z_t+b).
$$

$n$ 是训练样本数，$w\in\mathbb{R}^{6}$ 是权重，$b$ 是截距，$\lambda$ 控制正则化强度。`fit_ridge()` 先拟合线性输出，`ridge_prediction()` 再把负预测截为零。评价采用

$$
\operatorname{MAE}=\frac{1}{m}\sum_{t\in\mathcal{T}_{\mathrm{test}}}|\widehat c_t-c_t|.
$$

$m$ 为测试小时数，单位仍是每小时借车次数。训练用平方损失、报告用 MAE 时，可以进一步观察少量大误差是否影响模型选择。

扩展到 $N$ 个站点时，可把每站历史特征作为 $H^{(0)}\in\mathbb{R}^{N\times F}$。对无向站点图，一层 GCN 可写为

$$
H^{(\ell+1)}=\sigma\!\left(\widetilde D^{-1/2}\widetilde A\widetilde D^{-1/2}H^{(\ell)}W^{(\ell)}\right),
\quad \widetilde A=A+I,\quad \widetilde D_{ii}=\sum_j\widetilde A_{ij}.
$$

$A$ 表示站点连接或权重，$I$ 添加自环，$W^{(\ell)}$ 为可学习变换，$\sigma$ 为激活函数。输出每站的表示后，再接预测头。此时需要自己添加图模型；起步脚本提供的是单站岭回归。地理图和训练期流量图对应不同关系，可通过实验判断哪种关系更适合问题。按骑行方向统计的流量图有方向，使用上式时可以先明确对称化的方式。

## 对比实验与结果分析

下面的比较可以按兴趣选择，先固定一种问题做清楚。

| 改变的因素               | 保持一致的设置                   | 建议观察的输出                     |
| ------------------------ | -------------------------------- | ---------------------------------- |
| 本站、邻站均值、GCN      | 同一站点集合、时段和历史范围     | 总体与高峰 MAE，典型站点的预测曲线 |
| 2、6、24 小时历史        | 同一模型和测试集，说明参数量变化 | 验证与测试 MAE、训练耗时           |
| 地理图、流量图、单位矩阵 | 同一图模型、隐藏维度和训练预算   | 各站点误差，关系结构是否带来收益   |

还可以追问，某个模型总体 MAE 更低，是否只是更擅长预测低流量时段？模型在哪些突发高峰失误？若图模型改善很小，怎样区分图关系无效、训练不足和基线已经充分利用历史这几种解释？

若更关注表示学习，也可在训练时段遮蔽部分历史片段进行预训练，再研究少量预测样本下的效果。

预测时要区分“已经完成的一小时”和“正在预测的一小时”。记录反映已完成的骑行，缺车后放弃的需求和运营调车过程没有完整记录。库存调度还需要设定初始库存、容量和调车规则；后期容量快照应说明使用方式。

这些方向可联系回归、神经网络、图学习和序列建模。数据采用 NLOD 2.0，整理时注明来源。[官方数据与字段](https://oslobysykkel.no/en/open-data/historical) · [站点信息](https://oslobysykkel.no/en/open-data/realtime) · [许可](https://data.norge.no/nlod/en/2.0)

## 参考论文

- Kipf 与 Welling，2017，_Semi-Supervised Classification with Graph Convolutional Networks_。重点看归一化邻接矩阵和一层传播公式，理解站点特征如何与关系结合。[论文](https://arxiv.org/abs/1609.02907)
- Li 等，2018，_Diffusion Convolutional Recurrent Neural Network: Data-Driven Traffic Forecasting_。重点看空间依赖与时间预测如何组合，可据此设计自己的时空模块。论文研究道路速度，迁移到借还次数时需要重新定义输入和目标。[论文](https://arxiv.org/abs/1707.01926)
