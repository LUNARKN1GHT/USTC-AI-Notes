# 共享单车：从借还量预测到调度应用

共享单车站点会随着借车和还车不断变化：车太少时用户可能借不到，车太多时用户可能找不到空位归还。本任务使用 Oslo City Bike 的历史骑行记录，预测下一小时各站点的借还量，再通过提供的库存回放环境，研究预测能否帮助调度。

数据字段、预处理示例、模型公式和回放接口见 [共享单车数据集说明](共享单车数据集.md)。通用提交与评分要求见 [大作业要求与相关规则](../../大作业要求与相关规则.md)。[返回选题入口](../../期末大实验选题说明.md)

## 任务层次

前两部分为必做，用于基础得分评定；第三部分为“建议完成”，面向追求高分的同学，难度相较前面没有显著提升。第四部分为选做，鼓励追求满分或对相关内容感兴趣的同学进一步探究，可参考所列方向，也可自行提出其他有价值的想法。评分综合考虑工作量与质量，高质量地完成前三部分已经可以获得高分。

各层围绕同一组站点、时间划分和预测目标衔接，可以复用前面训练的模型和结果。

| 层次 | 任务 | 主要关注 |
| --- | --- | --- |
| 第一层：借还量预测建模与基线实验（必做） | 从原始行程构造预测样本，完成基线训练、评价与分析 | 数据处理、预测建模与完整实验流程 |
| 第二层：提出假设与研究预测（必做） | 自选合理方向设计预测方法，完成对照与分析 | 建模理由、实验公平性与证据 |
| 第三层：预测驱动调度（建议完成） | 把不同预测器接入给定回放器和固定策略 | 预测误差与借还服务效果的关系 |
| 第四层：开放探索与深入研究（选做） | 自选预测、表示、决策、回放设定或其他有价值的问题 | 问题价值、研究深度与证据质量 |

## 第一层：借还量预测建模与基线实验（必做）

完成一套从原始行程到预测结果的实验流程：在每个整点，根据此前已经发生的记录和当时已知的信息，预测接下来一小时的站点借车量与还车量。本层需要落实数据处理、样本构造、模型训练和评价，为第二层的预测研究及第三层的调度应用建立共同基础。

1. **整理行程并构造小时序列。** 选择一组站点并说明依据，检查时间、站点标识、缺失或异常记录等数据质量问题，说明采用的处理方式。按借出和归还各自发生的时间聚合计数，补齐连续小时。通过统计或可视化观察不同站点、时段的借还规律，说明这些特点对预测任务有什么启发。

2. **定义输入、目标与数据划分。** 将小时序列组织成可用于训练和评价的预测样本，明确历史信息范围、输入特征、预测目标及张量形状。用一条样本或时间示意说明输入与下一小时借还量的对应关系。按时间划分训练、验证和测试部分，处理历史不足的样本，并确认特征在预测时已经可用；需要估计的预处理统计量从训练部分计算。

3. **建立并训练基线模型。** 至少包含一个可解释的历史规则基线和一个可训练的预测模型，例如历史同期预测与线性回归，也可以选择其他合理方法。说明方法利用了什么信息，给出可训练模型的目标函数、主要设置和训练方式，通过验证部分选择设置。可以复用 `starter.py` 的单站处理和模型代码，在此基础上完成所选多站点的借车、还车预测，并说明自己的适配。

4. **完成评价与初步分析。** 在一致的数据和评价范围上比较基线，分别关注借车与还车的误差，用预测曲线或案例观察模型在哪些站点、时段表现较好或较差。结合总体指标与局部现象解释结果，指出后续值得研究的问题。确定模型设置后，使用测试部分报告最终表现。

报告中保留数据处理依据、输入输出示例、基线设置、指标比较和预测图表，使读者能够理解并复现这套流程。记录站点集合、划分与必要参数，供后续层次复用。第二层在此基础上提出并检验一个具体的改进假设。

## 第二层：提出假设与研究预测（必做）

围绕一个具体问题提出假设，选择适合的方法进行研究。下面列出一些参考方向，也欢迎自行拟定任何合理方向。

| 方向 | 可以参考的假设或问题 |
| --- | --- |
| 历史窗口与时间表示 | 更长的历史是否能改善预测？日周期、周末或高峰信息是否提供额外帮助？ |
| 邻站与空间关系 | 邻站历史是否提供额外信息？地理邻近与训练期站间流量形成的关系，哪一种更有用？ |
| 非线性与特征表示 | 非线性是否能利用线性模型遗漏的关系？不同表示能否改善特定站点或时段的预测？ |
| 损失与预测重点 | 对高峰或较大误差给予不同关注，是否会改变总体表现及关键时段表现？ |
| 自监督与样本规模 | 利用训练时段的历史片段学习表示，是否有助于较少预测训练样本的情形？ |

根据假设设计方法并完成对照实验，说明保持了哪些条件、改变了哪些因素，以及特征或模型为什么对应这个假设。模型类型与复杂度可以自行选择。

报告指标、曲线和相关案例，结合站点或时段差异分析结果。观察改进发生在哪里、哪些情况仍然失败，以及结果是否支持原先的判断。结果不符合预期时，也应依据实际证据解释，并提出可以继续检验的问题。

## 第三层：预测驱动调度（建议完成）

使用提供的 `replay.py` 库存回放器与基础调度规则，将基线预测器和自己研究的预测器接入，比较它们带来的借还服务效果。回放器维护站点库存、容量、在途车辆和等待还车队列，并按历史行程的时间顺序处理事件；接口与默认规则见数据集说明。

本层固定站点、需求事件、初始条件和调度规则，使主要差异来自预测器。结合预测误差、缺车借车失败、满站还车受阻和调车量，判断预测改进是否转化成服务改善。可加入不调车或只看当前库存的对照，帮助理解预测的作用。

选择相关的站点、时段或事件过程作案例分析，解释预测、库存和后续决策怎样共同产生结果。报告采用的回放设定，以及这些设定对解释结果的影响。

## 第四层：开放探索与深入研究（选做）

可以从前面发现的问题继续深入，也可以结合数据特点、课程内容或自己的兴趣提出新的研究问题。预测方法、站间关系、数据条件、服务目标、决策与回放机制等都可以成为研究对象。以下列出一些参考点，也欢迎自行提出其他有价值的想法，并用合理实验检验。

| 方向 | 可以研究的问题 | 可利用的信息或方法 |
| --- | --- | --- |
| 预测范围与时间结构 | 更远的预测范围、不同时间粒度或借还联合建模，会带来怎样的收益与困难？ | 多步预测、多尺度时间特征、联合目标 |
| 站间关系与表示学习 | 地理邻近与真实流量关系提供的信息是否不同？怎样学习或检验这些关系？ | 站点坐标、训练期流量图、图模型或自监督表示 |
| 数据条件与泛化 | 历史较少、缺失记录或需求变化时，哪些方法更可靠？ | 不同历史规模、明确构造的缺失情景、按时间或站点留出 |
| 不确定性与风险 | 预测区间或需求情景是否比单点预测更能帮助判断服务风险？ | 误差分布、分位数预测、概率评价与风险分析 |
| 预测与服务目标 | 总体误差下降为什么未必改善服务？哪些预测错误更影响缺车或满站？ | 分站点和分时段误差、服务指标、面向应用的损失或决策设计 |
| 调度规则与资源分配 | 何时调车、调多少、优先照顾哪些站点？不同资源预算下怎样取舍？ | 目标库存、触发阈值、距离与容量约束、优先级或优化方法 |
| 多步决策与交互学习 | 考虑未来多个时段是否值得？能否从回放反馈中学习决策？ | 滚动规划、区域协调、明确状态与动作后的强化学习 |
| 回放机制与情景假设 | 运输耗时、车辆位置或用户转站等设定，会怎样改变方法的相对表现？ | 扩展环境规则、参数敏感性、共同情景下的重新比较 |
| 服务差异与评价 | 总体表现与不同站点的服务水平是否一致？怎样衡量服务收益和搬运成本的权衡？ | 分组评价、服务覆盖、多目标比较与预算曲线 |
| 稳定性与效率 | 结论对站点选择、时间划分、初始库存或训练预算有多敏感？ | 重复实验、情景变化、模型简化与资源统计 |

可以选择一个方向深入，也可以形成自己的研究主线。说明问题为什么值得研究、方法与假设的关系，以及哪些结果能够支持判断；结合公平对照、指标与案例讨论收益、代价和适用条件。研究策略时明确可用信息与动作约束，研究新目标或新情景时建立相应基线。

当前回放把调拨作为整点的即时搬运。研究运输时间、调度车辆位置或用户改去其他站点等行为时，需要自行扩展相应环境规则，并在一致的环境中重新比较方法。

## 报告与复现

围绕“问题与假设—方法与设置—预测对照—调度评价—案例与讨论”组织报告，完整说明前两层的工作；完成第三、四层时，补充相应的调度评价、研究依据与实验。说明沿用的代码与自主完成的部分，保留配置、数据划分、必要参数及结果生成方式。具体交付格式以通用规则为准。

评价关注设计理由、对照公平性和结论的证据。各部分均应充分展示自己的思考与分析；评分综合考虑工作量和完成质量。
