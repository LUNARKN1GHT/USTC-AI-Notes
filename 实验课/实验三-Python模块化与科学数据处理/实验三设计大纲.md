# 实验三设计大纲：Python 模块化与科学数据处理

## 一、实验定位

实验一完成 Python 环境搭建与基础语法入门，实验二训练调试、函数、异常处理和类。实验三进一步解决两个问题：如何组织逐渐增长的代码，以及如何使用 NumPy、Pandas 处理机器学习中的表格数据。

本次实验的主线是：

> 识别模块来源 → 导入并使用科学计算库 → 完成数据处理 → 将处理函数封装为自定义模块 → 从 notebook 中复用并验证

实验采用与实验一相近的完整实验课组织方式。教师讲解、短练习和综合任务交替进行，不将内容压缩为单次集中讲授。

## 二、学习目标

完成实验后，学生应能够：

1. 区分模块、包、标准库、第三方库和项目自有代码。
2. 根据 Ruff 的导入分组理解不同依赖的来源和作用，并写出结构清晰的导入区。
3. 在正确的 Python 环境与 notebook kernel 中导入 NumPy、Pandas 和自定义模块。
4. 使用 NumPy 数组表示一维、二维数值数据，读取其形状、维数和数据类型。
5. 使用索引、切片、布尔筛选、聚合和向量化运算处理数值数据。
6. 解释二维数组中 `axis=0` 与 `axis=1` 的含义，并能检查运算结果的形状。
7. 使用 Pandas 读取表格数据，检查字段、类型、缺失值、重复值和异常值。
8. 使用 Pandas 完成行列选择、条件筛选、排序、新列计算、分组与聚合。
9. 将数据读取、检查、清洗、变换和统计拆分为职责明确的函数。
10. 将函数封装到独立 `.py` 模块，在 notebook 中导入并调用。
11. 使用 `assert` 检查列名、形状、数据范围和关键统计结果，并能够从头运行全部单元。

## 四、模块导入与 Ruff 规范

### 4.1 教学采用的四类导入

课堂将导入区按下列四种来源解释：

| 类别 | 作用 | 本次实验中的定位 |
| --- | --- | --- |
| Future imports | 选择或调整 Python 语言行为 | 说明其特殊位置，不作为主要练习 |
| Standard library | 使用随 Python 提供的通用工具 | 用路径处理等任务说明无需额外安装 |
| Third-party | 使用安装在当前环境中的外部库 | NumPy、Pandas 属于本组 |
| Project code | 复用当前项目自己编写的代码 | 自定义数据处理模块属于本组 |

四类导入之间用空行分隔，同一组内保持稳定顺序。分类的目的不仅是统一格式，还要帮助学生判断依赖来自哪里、是否需要安装以及导入失败时应检查什么。

### 4.2 与 Ruff 正式分类的关系

Ruff 默认进一步区分以下五类：

1. `future`；
2. `standard-library`；
3. `third-party`；
4. `first-party`；
5. `local-folder`。

课堂口径中的“项目自有代码”合并了后两类：

- `first-party` 表示当前项目中的模块，通常使用项目内的绝对导入；
- `local-folder` 通常对应带点号的相对导入。

本次采用平铺的实验目录，学生主要使用 first-party 模块。local-folder 只用于解释 Ruff 的分类，不要求学生搭建多层包结构。

### 4.3 Ruff 在实验中的作用

Ruff 用于：

- 对导入进行去重、分组和排序；
- 发现未使用的导入；
- 让学生比较自动修复前后的代码；
- 强化“导入来源不同，排错方向不同”的认识。

需要明确区分格式化与导入检查：导入排序由 Ruff 的 lint 规则负责，而不是仅依靠代码格式化。Ruff 是检查和落实规范的工具，模块的来源与职责才是分类依据。

### 4.4 本部分练习层级

1. 判断一组模块分别属于哪种来源；
2. 整理一段顺序混乱、存在重复项的导入区；
3. 使用 Ruff 检查并自动修复；
4. 删除或使用未被引用的导入；
5. 分别导入标准库、第三方库和本地模块；
6. 根据错误现象区分环境问题、文件位置问题和命名冲突。

## 五、NumPy 部分

### 5.1 知识结构

1. 从 Python 列表过渡到 NumPy 数组；
2. 数组的 `shape`、`ndim`、`size` 和 `dtype`；
3. 一维数组与二维特征矩阵；
4. 索引、切片和布尔筛选；
5. 逐元素算术与比较；
6. 求和、均值、极值和标准差等基础聚合；
7. 二维数组中的轴；
8. 广播的直观含义；
9. 向量化运算与显式循环的比较；
10. 特征矩阵的基础统计与标准化流程。

### 5.2 分阶段练习

- 练习 A：创建数组并判断结果的形状和数据类型；
- 练习 B：使用切片和布尔条件选取数据；
- 练习 C：分别沿两个轴计算统计量；
- 练习 D：使用向量化表达式完成特征变换；
- 练习 E：用 `assert` 检查结果形状、范围和统计性质。

本部分以“先判断形状，再进行运算”为统一要求，不追求覆盖大量函数。

## 六、Pandas 部分

### 6.1 知识结构

1. `Series`、`DataFrame` 与二维表格；
2. 从 CSV 读取数据；
3. 使用行数、列名和字段类型理解数据；
4. 选择单列、多列和满足条件的行；
5. 缺失值检查与简单处理；
6. 重复记录识别与处理；
7. 不合法取值和异常范围筛选；
8. 新增或修改计算列；
9. 排序与极值样本定位；
10. 按类别分组并计算统计量；
11. 将数值列转换为 NumPy 数组进行数值变换；
12. 将处理结果写回 DataFrame。

### 6.2 连续练习流程

Pandas 部分不拆成互不相关的 API 小题，而是围绕同一份练习数据连续完成：

> 读取 → 查看 → 发现问题 → 筛选和清洗 → 计算新字段 → 分组汇总 → 验证结果

每个阶段设置一个可观察的完成标志，使学生在综合实验前已经走过一次完整流程。

## 七、函数拆分与自定义模块

### 7.1 封装目标

学生先在 notebook 中完成可运行的数据处理过程，再按照职责拆分为：

- 数据读取；
- 数据质量检查；
- 数据清洗；
- 数值特征变换；
- 分组统计；
- 结果检查。

每个函数应通过参数接收数据并返回结果，避免依赖隐藏的全局状态。是否原地修改输入数据必须清楚、稳定，不让调用者猜测。

### 7.2 文件组织

本次采用简单、可观察的平铺结构：

```text
实验三/
├── 实验三_学生版.ipynb
├── data_utils.py
└── data/
    └── samples.csv
```

不要求学生创建正式 Python 包。模块文件应避免与标准库、NumPy 或 Pandas 同名。

### 7.3 导入与验证

学生应完成：

1. 将已经验证的函数移动到 `data_utils.py`；
2. 在 notebook 中导入模块或指定函数；
3. 重新运行调用代码；
4. 修改模块后正确刷新 notebook 中的定义；
5. 重启 kernel 并从头运行，证明程序不依赖残留状态；
6. 使用小规模 `assert` 检查模块接口。

`if __name__ == "__main__":` 只说明基本用途，可作为选做内容，不作为本次封装的核心要求。

## 八、综合实验框架

### 8.1 主题

**机器学习样本数据清洗与特征分析**

数据表包含样本编号、类别标签和若干数值特征，并有意识地保留少量数据质量问题。此时只确定数据结构和问题类型，不确定具体记录、数值和测试答案。

### 8.2 任务流程

1. 读取样本数据并确认基本结构；
2. 检查字段类型、缺失值、重复记录和取值范围；
3. 根据给定规则清洗无效记录；
4. 提取数值特征矩阵；
5. 使用 NumPy 完成特征统计和标准化；
6. 将变换结果加入清洗后的表格；
7. 使用 Pandas 按类别完成分组统计；
8. 定位具有代表性的极值或异常样本；
9. 将核心步骤封装进自定义模块；
10. 在 notebook 中导入模块并运行完整流程；
11. 使用公开自测检查形状、列名、范围和关键性质；
12. 对清洗规则、数据变化和统计结果作简短解释。

### 8.3 能力覆盖

综合实验应同时覆盖：

- Ruff 导入规范；
- 环境与路径检查；
- NumPy 数组和向量化；
- Pandas 表格清洗和分组；
- 函数职责划分；
- 自定义模块导入；
- 自动测试与从头运行；
- 对数据处理结果的解释。

综合实验不训练模型，避免把注意力从数据结构和模块化转移到算法接口。

## 十一、设计结论

本次实验不把模块、NumPy 和 Pandas 处理成三个并列且割裂的知识块，而是让它们服务于同一条数据处理主线：第三方库提供能力，自定义模块组织能力，Ruff 使依赖结构清晰且可检查，notebook 负责展示、调用和验证完整流程。

在进入讲义与题目制作阶段前，只需进一步确定数据集的字段主题、清洗规则数量、必做与选做题比例，以及教学平台对多文件和第三方依赖的支持情况。
