## 3. 模块、包和库

### 3.1 模块是什么

一个 Python 文件就是一个模块。例如 `data_utils.py` 是模块，里面可以保存变量、函数和类：

```python
# temperature_utils.py
def celsius_to_fahrenheit(value: float) -> float:
    return value * 1.8 + 32
```

另一个文件可以导入它：

```python
from temperature_utils import celsius_to_fahrenheit

print(celsius_to_fahrenheit(20))
```

导入模块时，Python 会找到对应文件，执行模块顶层代码，并将其中定义的对象放入模块的命名空间。因此模块顶层不宜放置大量会立刻运行的实验代码。

### 3.2 包和库

- **模块**：一个可导入的 `.py` 文件；
- **包**：按目录组织的一组模块；
- **库**：从用途角度对一组可复用工具的称呼，可能包含多个包和模块。

NumPy 和 Pandas 是第三方库。`numpy`、`pandas` 是导入时使用的包名。本次实验只要求创建一个平铺的 `data_utils.py` 模块，不要求发布自己的包。

### 3.3 导入方式与命名空间

导入整个模块：

```python
import math

print(math.sqrt(9))
```

只导入一个名称：

```python
from math import sqrt

print(sqrt(9))
```

使用惯用别名：

```python
import numpy as np
import pandas as pd
```

对于自定义模块，实验中推荐先导入模块：

```python
import data_utils

data = data_utils.load_data("data/samples.csv")
```

这种写法能直接看出函数来自哪里。避免：

```python
from data_utils import *
```

星号导入会把许多名称放入当前命名空间，容易发生覆盖，也难以判断一个函数来自哪个模块。

## 4. 用 Ruff 理解导入结构

### 4.1 四类教学分组

观察下面的导入区：

```python
from __future__ import annotations

from pathlib import Path

import numpy as np
import pandas as pd

import data_utils
```

四组分别表示：

1. **Future imports**：选择或调整 Python 语言行为，位置最特殊；
2. **Standard library**：随 Python 安装，例如 `pathlib`；
3. **Third-party**：安装在当前环境中的第三方依赖，例如 NumPy、Pandas；
4. **Project code**：当前项目自己编写的模块，例如 `data_utils`。

Ruff 正式区分五类：`future`、`standard-library`、`third-party`、`first-party` 和 `local-folder`。本实验把后两类合称为“项目自有代码”：

- `first-party` 通常是当前项目中的绝对导入；
- `local-folder` 通常是 `from .module import name` 形式的相对导入。

本实验没有多层包结构，因此主要使用 first-party 导入。

### 4.2 为什么来源不同很重要

出现 `ModuleNotFoundError` 时，不同来源对应不同检查方向：

| 来源     | 优先检查                                             |
| -------- | ---------------------------------------------------- |
| 标准库   | 文件名是否误用了标准库名称，Python 环境是否异常      |
| 第三方库 | 是否安装在当前解释器或 kernel 中                     |
| 项目代码 | 文件是否存在、当前工作目录是否正确、名称是否拼写一致 |

不要把自己的文件命名为 `numpy.py`、`pandas.py`、`pathlib.py` 或 `random.py`。否则 Python 可能先导入这个同名文件，产生“模块存在但缺少某个属性”的混乱错误。

### 4.3 Ruff 检查与修复

在实验目录中运行：

```bash
ruff check data_utils.py
```

本实验已经提供 `ruff.toml`，其中启用了导入排序和常见错误检查。自动修复能够安全修改的问题：

```bash
ruff check --fix data_utils.py
```

检查但不修改代码时不要添加 `--fix`。Ruff 的 `I001` 规则负责导入去重、分组和排序。`F401` 表示导入了名称却没有使用。

`ruff format` 负责代码格式，但目前不会单独完成导入排序。因此需要先执行 lint 修复，再按需格式化：

```bash
ruff check --fix data_utils.py
ruff format data_utils.py
```

Ruff 官方说明：[导入排序 I001](https://docs.astral.sh/ruff/rules/unsorted-imports/)、[格式化与导入排序](https://docs.astral.sh/ruff/formatter/#sorting-imports)。

## 5. NumPy：带形状的数值数组

### 5.1 数组与列表

Python 列表可以保存不同类型并改变长度。NumPy 的 `ndarray` 通常保存同一种数据类型，并具有固定的维度和规则形状：

```python
import numpy as np

values = np.array([2.0, 4.0, 6.0, 8.0])
matrix = np.array(
    [
        [5.1, 3.5, 1.4],
        [4.9, 3.0, 1.4],
        [7.0, 3.2, 4.7],
    ]
)
```

检查数组：

```python
print(values.shape, values.ndim, values.size, values.dtype)
print(matrix.shape, matrix.ndim, matrix.size, matrix.dtype)
```

- `shape`：每个轴的长度；
- `ndim`：轴的数量；
- `size`：元素总数；
- `dtype`：元素的数据类型。

`matrix.shape == (3, 3)` 表示 3 行、3 列。对于机器学习数据，通常将每一行看作一个样本，每一列看作一个特征。

### 5.2 索引和切片

```python
print(matrix[0, 1])   # 第 0 行、第 1 列
print(matrix[0])      # 第 0 行
print(matrix[:, 1])   # 所有行的第 1 列
print(matrix[:2, :2]) # 前两行、前两列
```

NumPy 的基础切片通常返回原数组的视图，而不是完全独立的复制品。修改切片有可能影响原数组。需要独立数据时明确调用 `.copy()`。

### 5.3 布尔筛选

比较会产生布尔数组：

```python
scores = np.array([0.92, 0.45, 0.81, 0.30])
mask = scores >= 0.8

print(mask)
print(scores[mask])
```

二维数据可以按行筛选：

```python
row_mask = matrix[:, 0] >= 5.0
selected_rows = matrix[row_mask]
```

布尔条件的形状必须与它要筛选的轴兼容。筛选结果不对时，先打印条件数组及其 `shape`。

### 5.4 逐元素运算与向量化

NumPy 的算术默认逐元素进行：

```python
values = np.array([1.0, 2.0, 3.0])

print(values + 1)
print(values * 2)
print(values**2)
```

与逐个追加结果相比，向量化表达式更接近数学公式：

```python
# 不推荐：只是为了展示逐元素循环
result = []
for value in values:
    result.append((value - 2) / 0.5)

# 推荐
result = (values - 2) / 0.5
```

本实验不以运行时间测量为重点。向量化首先改善的是表达清晰度，并为后续张量计算建立习惯。

### 5.5 聚合与轴

```python
matrix = np.array(
    [
        [1.0, 10.0, 100.0],
        [2.0, 20.0, 200.0],
        [3.0, 30.0, 300.0],
    ]
)

print(matrix.mean())
print(matrix.mean(axis=0))
print(matrix.mean(axis=1))
```

对于形状为 `(样本数, 特征数)` 的二维数组：

- `axis=0` 消去样本轴，得到“每个特征一个结果”；
- `axis=1` 消去特征轴，得到“每个样本一个结果”。

不要只背“0 是列、1 是行”。更稳定的判断方法是：**指定哪个轴，就沿哪个轴聚合，结果中该轴消失。**

### 5.6 广播与标准化

设特征矩阵形状为 `(n_samples, n_features)`，每列均值和标准差的形状都是 `(n_features,)`：

```python
means = matrix.mean(axis=0)
standard_deviations = matrix.std(axis=0)
standardized = (matrix - means) / standard_deviations
```

NumPy 从最右侧维度比较形状。这里 `(n_features,)` 可以与矩阵的最后一个维度匹配，因此每一行都会减去同一组列均值。这个机制称为广播。

标准分数定义为：

$$
z_{ij} = \frac{x_{ij} - \mu_j}{\sigma_j}.
$$

本实验统一使用总体标准差，即 NumPy `std()` 的默认设置。标准化后，每一列的均值应接近 0，总体标准差应接近 1。浮点数存在舍入误差，应使用 `np.allclose()`，不要要求结果与 0 或 1 完全相等。

若某列标准差为 0，说明该列所有值相同，直接除法会产生无效结果。数据处理函数应主动拒绝这种输入。

NumPy 入门参考：[数组基础](https://numpy.org/doc/stable/user/absolute_beginners.html)、[广播规则](https://numpy.org/doc/stable/user/basics.broadcasting.html)。

## 6. Pandas：带字段名的表格

### 6.1 Series 与 DataFrame

- `Series` 是一维带标签数据；
- `DataFrame` 是二维表格，每列可以有自己的数据类型。

选择一列返回 `Series`；使用列名列表选择多列返回 `DataFrame`。

```python
data_path = Path("data") / "samples.csv"
```

### 6.3 选择列和筛选行

```python
feature_1 = data["feature_1"]
features = data[["feature_1", "feature_2", "feature_3"]]

class_a = data[data["label"] == "A"]
valid_labels = data[data["label"].isin(["A", "B", "C"])]
```

组合多个条件时，每个条件放在括号中，并使用 `&` 或 `|`：

```python
selected = data[(data["feature_1"] > 0) & (data["label"] == "B")]
```

不能在两个 `Series` 条件之间直接使用 Python 的 `and` 或 `or`。

需要同时明确行与列时使用 `.loc`：

```python
selected_features = data.loc[data["label"] == "B", ["feature_1", "feature_2"]]
```

### 6.4 缺失值和重复值

检查缺失值：

```python
print(data.isna().sum())
print(data.isna().sum().sum())
```

不要用 `value == np.nan` 判断缺失值，应使用 `isna()` 或 `notna()`。

检查重复记录：

```python
duplicate_mask = data.duplicated()
print(data[duplicate_mask])
```

删除时默认保留第一次出现的记录：

```python
without_duplicates = data.drop_duplicates()
```

根据必需字段删除缺失记录：

```python
required = ["sample_id", "label", "feature_1", "feature_2", "feature_3"]
complete = data.dropna(subset=required)
```

“删除、填充还是保留”由任务语义决定，不存在对所有数据都正确的统一选择。本实验的清洗规则已经明确要求删除必需字段不完整的记录。

### 6.5 类型转换与非法文本

来自 CSV 的数值列可能混入文本。使用：

```python
converted = pd.to_numeric(data["feature_1"], errors="coerce")
```

`errors="coerce"` 会把无法转换的值记为缺失。这样可以统一使用缺失值检查，而不是为每个字符串写异常分支。

### 6.6 复制与原地修改

数据清洗函数通常不应偷偷修改调用者持有的原始表：

```python
cleaned = data.copy()
```

随后对 `cleaned` 操作并返回它。这样 notebook 可以同时保留 `raw_data` 与 `cleaned_data`，比较清洗前后的变化。

优先使用方法返回的新对象，不依赖大段 `inplace=True` 链式修改。清晰的数据流比少写一个变量更重要。

### 6.7 新增列与 NumPy 转换

从 DataFrame 提取数值矩阵：

```python
feature_columns = ["feature_1", "feature_2", "feature_3"]
values = data.loc[:, feature_columns].to_numpy(dtype=float)
```

把变换结果写回副本：

```python
result = data.copy()
result.loc[:, ["z_feature_1", "z_feature_2", "z_feature_3"]] = transformed
```

Pandas 负责字段名、行筛选和表格组织；NumPy 负责规则数值数组上的向量化运算。两者不是相互替代，而是各自处理擅长的问题。

### 6.8 分组与聚合

按标签统计每组数量：

```python
counts = data.groupby("label", as_index=False).agg(
    sample_count=("sample_id", "size")
)
```

命名聚合可以明确指定“输出列名—输入列—聚合方法”：

```python
summary = data.groupby("label", as_index=False).agg(
    sample_count=("sample_id", "size"),
    mean_feature_1=("feature_1", "mean"),
)
```

这体现了“拆分—应用—合并”：先按标签拆成多组，对每组应用统计，再合并为结果表。

Pandas 参考：[读取表格数据](https://pandas.pydata.org/docs/getting_started/intro_tutorials/02_read_write.html)、[选择表格子集](https://pandas.pydata.org/docs/getting_started/intro_tutorials/03_subset_data.html)、[缺失数据](https://pandas.pydata.org/docs/user_guide/missing_data.html)。

## 7. 从 notebook 重构到模块

### 7.1 为什么先运行再重构

直接同时处理“业务逻辑”和“跨文件导入”会增加排错难度。推荐顺序：

1. 在 notebook 中用少量数据验证处理思路；
2. 将一个步骤写成函数；
3. 用 `assert` 验证函数；
4. 将函数移动到 `data_utils.py`；
5. 重新导入并运行同一组测试。

如果移动前就不正确，问题在处理逻辑；移动前正确、移动后失败，优先检查模块路径、名称和缓存。

### 7.2 一个函数负责一个步骤

本次模块包含六个接口：

```text
load_data()                读取 CSV
inspect_data()             汇总数据质量信息
clean_data()               按规则清洗
standardize_features()     标准化数值特征
summarize_by_label()       按标签汇总
find_most_unusual_sample() 定位标准化距离最大的样本
```

调用关系为：

```text
CSV → load_data → raw_data
                  ├─ inspect_data → quality_report
                  └─ clean_data → cleaned_data
                                   ├─ standardize_features → transformed_data
                                   ├─ summarize_by_label → summary
                                   └─ find_most_unusual_sample → sample_id
```

函数通过参数接收数据，通过 `return` 返回结果。不要让函数依赖 notebook 中恰好存在的全局变量。

### 7.3 修改模块后的缓存

Python 在一次进程中通常只执行模块的首次导入。修改 `data_utils.py` 后，再次写 `import data_utils` 不一定会重新读取文件。

实验中最稳妥的做法是：

1. 保存 `data_utils.py`；
2. 重启 notebook kernel；
3. 从导入单元开始重新运行。

开发过程中也可以使用 `importlib.reload()`，但提交前仍必须用全新 kernel 从头验证。

### 7.4 路径应相对于实验目录

推荐：

```python
from pathlib import Path

data_path = Path("data") / "samples.csv"
```

不要提交只在自己电脑上成立的绝对路径：


### 8.3 异常样本分数

对于三个标准化特征，定义：

$$
s_i = z_{i1}^2 + z_{i2}^2 + z_{i3}^2.
$$

分数最大的样本在这组数据的标准化特征空间中离中心最远。本实验只把它称为“最不寻常样本”，不把它直接判定为错误数据。统计上的极端与业务上的无效是不同概念。

并列时保留先出现的样本。NumPy 的 `argmax()` 会返回第一次出现的最大值位置，适合实现这一规则。

### 8.4 公开自测的意义

公开测试会检查：

- 数据质量报告的字段和值；
- 清洗后数据的形状、唯一性和合法性；
- 标准化列的均值和总体标准差；
- 分组统计的标签顺序和样本数；
- 最不寻常样本编号；
- 原始 DataFrame 是否被函数意外修改。

不要通过修改 `assert` 或直接写死预期答案让测试变绿。函数还应能够处理结构相同、具体数值不同的数据。

## 9. 常见错误速查

### 9.1 `ModuleNotFoundError: No module named 'pandas'`

先在 notebook 中打印 `sys.executable`，再用对应解释器安装依赖。不要看到错误后反复在不同终端中运行 `pip install`。

### 9.2 `ModuleNotFoundError: No module named 'data_utils'`

检查：

- 文件是否确实名为 `data_utils.py`；
- notebook 与模块是否在同一目录；
- 当前工作目录是否正确；
- 文件名是否出现隐藏的 `.txt` 后缀。

### 9.3 `AttributeError: module 'pandas' has no attribute ...`

检查实验目录是否存在自己创建的 `pandas.py` 或名为 `pandas` 的文件夹。删除或改名后重启 kernel，避免旧模块仍留在内存中。

### 9.4 `ValueError: operands could not be broadcast together`

打印参与运算的所有数组 `shape`，从最右侧比较维度。不要在没看形状前反复加括号或转置。

### 9.5 `ValueError: The truth value of a Series is ambiguous`

检查是否对 Pandas 条件使用了 `and`、`or`，或者直接把整个 `Series` 放进 `if`。逐元素组合条件使用 `&`、`|`，并给每个条件加括号。

### 9.6 修改模块后结果没有变化

保存文件，重启 kernel，再从头运行。不要只重新执行调用函数的最后一个单元。

### 9.7 `SettingWithCopyWarning` 或赋值结果不稳定

在函数开头创建明确副本，并使用 `.loc` 给列赋值。不要对来源不清楚的筛选结果连续链式赋值。
